# NBA dashboard audit

Integration update: this is the historical audit report, retained as evidence. Its line references and command results describe the original audit snapshot (`a867691`), not the subsequently rebased source. See [AUDIT_INTEGRATION.md](AUDIT_INTEGRATION.md) for the hotfix reconciliation, current test result, classified commits, model-schema safeguard and review-only release rule.

Audited 29 October 2026 (Australia/Sydney), starting at `bb2bcebf1acacfd2cd8d74ee2ad6d54c9fc543e9` on a new local branch, `codex-audit`. At the time of that audit, nothing was pushed or deployed. The bundled database and trained model were preserved. Descriptions explicitly identify original behavior where it was fixed.

The dashboard is useful for exploring projections, but its betting probabilities and value/confidence labels are not validated well enough to treat as reliable betting recommendations. Several concrete correctness and security problems were fixed. Availability-history leakage, coherent same-game pricing, calibration, current rosters and reliable refreshes still need work.

## Statistical interpretation and limits

The negative-binomial plus Gaussian-copula design is a defensible **starting approximation** for overdispersed basketball counts. Its orientation is correct. It does not by itself validate the probabilities: learned means, residual variance, discrete marginal fit, omitted dependencies, projected minutes and lineup availability all matter. Current DD/TD integration is logically inconsistent with the component counts. A positive average prediction improvement should not be translated into a reliable bettor's edge.

The initial points improvement is about 0.21 points per appearance, not enough to overwhelm the demonstrated uncertainty in dispersion and lineup state. On 4,206 post-fix test appearances with 15+ teammate points absent, the with/without-feature comparison reduces points under-prediction from **0.864 to 0.226**, rather than eliminating it; overall MAE moves from **5.331 to 5.266**. This still uses hindsight availability, so it does not establish the same benefit pregame. Blocks remain worse than a plain average in the extended diagnostic (MAE **0.605 vs 0.599**). Steals in this split improve slightly (**0.821 vs 0.840**), so “no better” is too absolute; this still does not validate steals prices. Team market-vs-Elo claims reproduce, but market-based match pricing is a price comparison against one bookmaker's source, not a broad market consensus or independently proven model edge. If source moneylines are absent, the match winner chance even falls back to the spread-based normal model despite the “market” label.

Only local code/data and selected public provider responses were audited. The live Fly deployment, real secret state, historical server logs, billing and backups were not inspected. No production users' bets were changed. No paid odds request, live penetration test, load attack or provider access-control bypass was performed. Database consistency checks do not prove every historical score/roster externally correct. No full schedule enumeration across all seasons or complete external roster reconciliation was performed. Further model evaluation must begin with repaired dates, data flags and true pregame availability; the post-fix report is still not a leak-free production-performance claim.

Local browser review used a temporary database copy with refresh disabled and a synthetic display name. Checked light/dark views, expanded games, market accessibility states and an unsaved draft slip. No bet or pick was posted. Narrow-view findings are observations, not exhaustive assistive-technology testing.

## Ranked next changes

### Five changes most likely to improve prediction accuracy

1. **Rebuild pregame history correctly:** store true tip timestamps/Eastern dates, reconcile missing/incomplete games and archive injury/lineup snapshots. Remove hindsight participation leakage.
2. **Validate and calibrate distributions on later predictions:** estimate dispersion from rolling out-of-fold residuals; reserve separate correlation/calibration and final test periods.
3. **Model playing time and roster changes explicitly:** dated rosters, expected minutes and injury uncertainty, instead of last-team assumptions and weighted absence shortcuts.
4. **Make all joint events coherent:** official five-category DD/TD, player components, team scores, totals and margins from consistent simulations; validate dependence/tails before pricing overlaps.
5. **Broaden independent evaluation:** several seasons and rolling cutoffs, actual timestamped bookmaker lines, role/market calibration and player/game-block uncertainty; retain simple baselines where they win.

### Five changes most likely to improve trust and safety

1. **Finish security hardening:** production fail-closed auth, individual sessions, rate limits and a complete move away from unsafe inline templates. Deploy the reviewed stored-XSS and error-redaction fixes first.
2. **Replace “safe/strong/value” certainty with tested evidence:** require fresh real prices, disclose sample size/model uncertainty and suppress unsupported parlay EV.
3. **Make refreshes and storage recoverable:** single-flight managed jobs, atomic versioned models/slates, visible last-success/error status and off-host backup/restore tests.
4. **Use authorized, traceable feeds:** resolve Rotowire/ESPN permission and continuity risks; display bookmaker/source/time, validate schemas and never silently use stale prices.
5. **Gate releases with tests and accessible review:** run the new suite in deployment, version artifacts with code, finish keyboard/screen-reader support and distinguish model prices from executable bookmaker quotes.
